# v1.1計画: 導入体験の固定化（外部Dir E2E）+ 互換経路の1リリース縮退

## 概要
`wcf` の no-build 体験を「壊れにくく・迷いにくく」するため、今回の実装対象を次の2点に固定する。
1) 外部ディレクトリでの完走をCIで担保（PR軽量 + 夜間拡張）
2) `@wcf` / `index` を1リリース猶予で縮退し、`boot` 中心へ収束

## 実装対象
1. 外部Dir E2E固定化（CI）
2. `@wcf` / `index` 互換経路の縮退開始（警告付き維持）

## 非対象
- `wcf create`（one-shot新コマンド）
- MCP連携拡張
- `bun create` のCI自動実行（手動確認 + ドキュメント運用）

## 変更仕様
### 1) 外部ディレクトリE2E固定化（PR軽量 + 夜間拡張）
- npm scripts追加
  - `wcf:smoke:npm`: `node scripts/wcf/smoke-ttfr.js --runner npm`
  - `wcf:smoke:bunx`: `node scripts/wcf/smoke-ttfr.js --runner bunx`
- 新規 Workflow: `.github/workflows/wcf-experience.yml`
  - trigger: `pull_request` / `schedule` / `workflow_dispatch`
  - PR: `wcf:smoke:node` + `wcf:smoke:bun`
  - 夜間: `wcf:smoke:npm` + `wcf:smoke:bunx`

### 2) 互換経路の1リリース縮退（`boot`中心化）
- 現リリース（N）: `@wcf` / `index` は動作維持 + 警告
- 次リリース（N+1）: `@wcf` / `index` 廃止（`boot`のみ）
- `scripts/wcf/core.js`
  - `createPage --entry @wcf|index` で `W_ENTRY_DEPRECATED` を warnings に追加
  - `vendorInstall` で互換shimを生成
    - `vendor/components/<prefix>/index.js`（`boot.js` へ委譲）
    - `vendor/components/<prefix>/autoload/<suffix>.js`（`components/<suffix>.js` へ委譲）

## テスト
- `tests/wcf-vendor.spec.ts`
  - `components/**` に加えて `index.js` / `autoload/*.js` の存在確認
- `tests/wcf-page.spec.ts`
  - `entry=@wcf|index` で page 生成成功 + `W_ENTRY_DEPRECATED` 検証

## docs 更新
- `README.md`
- `docs/knowledge/wcf-cli.md`
- `scripts/wcf/generate-docs.js` 経由の生成docs
- 方針を統一: 推奨 `--entry boot`、互換 `@wcf|index`（deprecated）

## 検証
- `npm run vendor:build`
- `npm run vendor:check`
- `npm run wcf:docs:check`
- `npx vitest run tests/wcf-vendor.spec.ts tests/wcf-page.spec.ts`
- `npm run wcf:smoke:node`
- `npm run wcf:smoke:bun`
- 必要時 `npm run wcf:smoke:npm` / `npm run wcf:smoke:bunx`
