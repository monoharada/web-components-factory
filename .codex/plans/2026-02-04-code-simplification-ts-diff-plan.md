# TS差分のコード簡素化（このブランチの差分 .ts 全体）

## 目標
このブランチの差分に含まれる .ts ファイルを対象に、挙動を変えずに簡素化する。

## 背景
多数の差分が存在し、簡素化の対象は「このブランチの差分 .ts 全体」に確定。

## スコープ
- やること：
  - このブランチの差分に含まれる .ts ファイルのみを簡素化
  - 既存ヘルパー/ユーティリティの探索と再利用
- やらないこと：
  - 挙動変更・公開API変更・大規模リファクタ
  - 依存追加、ビルド/設定の変更
  - .ts 以外のファイル編集

## 前提 / 制約
- 実装前にナレッジ/規約と既存ユーティリティを確認
- 差分が大きい場合は code-simplifier の規定に従い `preview` に降格
- 既存の CSS/コンポーネント設計規約は遵守（該当時のみ）

## 変更内容（案）
### データ / バックエンド
該当なし

### UI / UX
- 既存ロジックの早期return・ネスト削減・重複削除
- 既存ユーティリティへの置換（同等挙動のみ）

### その他（Docs/Marketing/Infra など）
該当なし

## 受入基準
- [ ] 対象が「差分の .ts 全体」である
- [ ] 挙動変更が発生していない
- [ ] 既存ユーティリティが優先的に使われている
- [ ] 依存追加や大規模リネームがない
- [ ] 検証結果が報告されている

## リスク / エッジケース
- 既存差分が多く、意図しない範囲に波及する可能性
- 同等ユーティリティの挙動差による微妙な変更

## 作業項目（Action items）
1. 差分 .ts 一覧の確定（完了条件: `git diff --name-only` から .ts のリストが取れる）
2. 規約/設定の再確認（完了条件: 参照済みファイル一覧がある）
3. 既存ユーティリティ探索（完了条件: 採用/不採用理由付きでメモ化）
4. ファイル単位の簡素化方針を整理（完了条件: 変更案が整理されている）
5. `apply`/`preview` モード決定（完了条件: モードが明確）
6. 影響の少ない変更から実装（完了条件: 小さな差分で適用）
7. 検証の実行または代替確認（完了条件: 結果が記録されている）
8. code-simplifier 形式で報告（完了条件: 所定フォーマットで報告）

## テスト計画
- 可能なら `npm run lint` / `npm run type-check` / `npm test`
- 実行できない場合は理由と代替の静的確認を記載
