# カード作例5（横レイアウト崩れ）修正プラン v2

## 目標
作例5の横レイアウトを、添付画像（横一・右側にボタンブロックがある構成）に一致させる。

## 背景
現状の横レイアウトでは、カード内部のレイアウトが縦方向に崩れ、ボタンが下部に沈んで横並びにならない。提供いただいた参考では、**左に画像・中央に本文・右にアクションブロック**の3カラム構成で揃っている。

## スコープ
- やること：
  - 横レイアウト時のみ、カード内部を**3カラム構成（media / main / actions）**にする
  - 右側アクションブロックを固定幅/中央寄せで表示し、ボタンを横並び
  - 画像と本文の縦位置を揃える
- やらないこと：
  - `dads-card` 本体仕様変更
  - 縦レイアウトの見た目変更

## 前提 / 制約
- 実装対象は `src/demos/showcase-components.ts` の作例5のみ
- CSSは `css-writing-rules` のルールに従う（トークン優先・!important禁止）

## 変更内容（案）
### データ / バックエンド
- 該当なし

### UI / UX
- 横レイアウト時に `dads-card` の `layout="horizontal"` を使わず、**作例5専用の3カラムレイアウト**を組む（`dads-card` 内の slot を活かしつつ `display: grid` で制御）
- `sub` を右カラムに固定配置し、**ボタン2つを横並びで中央寄せ**にする
- 画像は左カラム、本文は中央カラム、アクションは右カラムの構成にする

### その他（Docs/Marketing/Infra など）
- VRT更新（横レイアウトのスナップショット差分を反映）

## 受入基準
- [ ] 横レイアウトが「画像 / 本文 / ボタンブロック」の3カラム構成になる
- [ ] ボタンが右カラムで横並び・中央寄せになる
- [ ] 画像と本文の高さ/揃えが自然で、崩れがない
- [ ] 縦レイアウトは現状維持
- [ ] VRTがグリーン

## リスク / エッジケース
- `dads-card` の `layout="horizontal"` を使わない場合、他の例との一貫性が薄れる
- grid構成の調整でボタン領域の高さが崩れる可能性
