# KPIカード（作例4）レビュー＆再設計プラン

## 目標
- KPIカードの認知負荷を下げ、情報階層とグルーピングを明確化する
- リンク/状態/装飾の色役割を整理し、迷いのない操作感にする
- Figmaに沿った余白・密度設計に調整する（タグは維持）

## 背景
- KPIカードはダッシュボード用途で、短時間で「主要値・差分・進捗」を読み取る必要がある
- 画像を見る限り、KPI値と差分の近接が不足し、進捗の意味もやや曖昧に見える

## スコープ
- やること：
  - KPIカードの情報階層・余白・グルーピング・リンク明確化の見直し
  - a11y観点での視認性/操作性チェックと改善案整理
  - 修正案に基づく詳細実装プラン作成
- やらないこと：
  - タグ（Android / iOS）のデザイン変更
  - 数値・文言の変更
  - KPIカード以外の作例変更

## 前提 / 制約
- DADS準拠、Practical UI原則は補助輪として適用
- タグは**変更対象外**
- 文言・数値は維持（表示/配置は調整可能）
- リンク/状態/装飾の色役割は混在させない
- タイトルリンクは行全体クリック
- 進捗の意味明確化は視覚ラベル追加まで許容

## 変更内容（案）
### データ / バックエンド
- 該当なし

### UI / UX
- KPI値＋差分を同一グループとして強化
- 進捗の意味を視覚ラベルで明示
- タイトルリンクは行全体クリック化
- 余白と区切り線を再調整し階層を明確化

### その他（Docs/Marketing/Infra など）
- VRTスナップショット更新

## 受入基準
- [ ] KPI値と差分が同一グループとして認識できる
- [ ] 進捗バーと件数の意味関係が一目で分かる（ラベルあり）
- [ ] タイトルリンクが行全体クリックとして機能・視認できる
- [ ] タグデザインは変更されていない
- [ ] a11y観点（focus-visible/色依存回避/hover分岐）が満たされる

## リスク / エッジケース
- 余白調整で可読性が落ちる可能性
- hover強調がフォーカスリングと競合する可能性
- 進捗ラベル追加で情報量が過多になるリスク

## 作業項目（Action items）
1. KPI/差分/進捗のグルーピング設計（完了条件: 距離と整列の方針が決まる）
2. 進捗ラベルの配置と文言を決定（完了条件: 配置とスタイルが確定）
3. タイトルリンクを行全体クリック化（完了条件: ブロックリンク化が完了）
4. 余白・区切り線の再調整（完了条件: 階層が明確に見える）
5. a11yチェック項目の確認・適合方針（完了条件: focus-visible/hover/色依存を満たす）
6. VRT更新（完了条件: スナップ更新済み）
