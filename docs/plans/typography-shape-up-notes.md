# Shape Up メソドロジー適用メモ

## 🎯 Key Shape Up Principles Applied

### 1. Fixed Time, Variable Scope（固定時間、可変スコープ）
- **Before**: 16-20時間の見積もり、12タスク
- **After**: 1週間固定、スコープは調整可能

### 2. Appetite, Not Estimates（見積もりではなくアペタイト）
- **Before**: 詳細な時間見積もり
- **After**: Small Batch（1週間）のアペタイト設定

### 3. Hill Charts Instead of Tasks（タスクリストではなくヒルチャート）
- **Before**: 12個の詳細タスク
- **After**: 3つの不確実性として管理

### 4. Circuit Breaker（サーキットブレーカー）
- **Before**: 全機能実装が前提
- **After**: Day 2でGo/No-Go判断、スコープ調整可能

## 📊 Before vs After Comparison

| 項目 | 従来アプローチ | Shape Up アプローチ |
|------|--------------|-------------------|
| 期間 | 3-4日（16-20時間） | 1週間固定 |
| スコープ | 全機能実装 | Must/Nice/Skip で分類 |
| タスク管理 | 12個の詳細タスク | 3つの不確実性 |
| 完了基準 | 完璧な実装 | Good Enough |
| リスク管理 | 詳細な緩和策 | Day 2 Go/No-Go |

## 🚀 Shape Up Benefits

1. **明確な終了点**: 金曜日に必ず出荷
2. **柔軟性**: スコープ調整で時間内完了を保証
3. **学習重視**: 完璧より反復を優先
4. **ストレス軽減**: 完璧主義からの解放

## 💡 Key Insights

### "これが分かれば下り坂"の考え方
各不確実性に対して、解決すべき核心的な問題を定義。
これが解決されれば、あとは実装作業（下り坂）になる。

### Nice to Have リスト
実装したいが必須ではない機能を明確化。
時間があれば取り組むが、なくても出荷可能。

### Cool-down の重要性
金曜日は新機能追加ではなく、統合と申し送りに専念。
次サイクルへの橋渡しを重視。

## 📝 Practical Takeaways

1. **毎日の質問を習慣化**
   - 「これは今週必須か？」
   - 「金曜日になければ困るか？」

2. **ヒルチャートで進捗管理**
   - タスクの%完了ではなく
   - 不確実性の解決度で測定

3. **出荷を最優先**
   - 完璧な計画 < 実際の出荷
   - 学習と反復を重視
