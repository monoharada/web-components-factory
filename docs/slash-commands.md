# 🔸 Claude Code Slash Commands Guide

## 概要

Claude Codeのスラッシュコマンドは、開発ワークフローを効率化するための専用コマンドです。  
これらのコマンドを使用することで、計画から実装、レビュー、振り返りまでの一連の作業を体系的に進められます。

## 📋 標準スラッシュコマンド

### `/design` - 実装計画作成
**目的**: タスクの分解と技術設計

**実行内容**:
1. 要件の分析
2. タスクの最小単位への分解（30分〜2時間）
3. 技術的決定事項の文書化
4. リスクと依存関係の特定
5. テスト戦略の策定

**出力**:
- `docs/plans/feature-YYYYMMDD-{name}.md` に実装計画を作成

**使用例**:
```
/design アコーディオンコンポーネントの実装
```

---

### `/revise` - 実装計画の修正
**目的**: 計画の更新と調整

**実行内容**:
1. 既存の実装計画をレビュー
2. 新しい要件や制約の反映
3. タスクの再評価と調整
4. リスクの再評価

**使用例**:
```
/revise アクセシビリティ要件を追加
```

---

### `/implement` - 実装実行
**目的**: 計画に基づいた実装

**実行内容**:
1. TDDアプローチの適用
   - テスト作成
   - 最小実装
   - リファクタリング
2. 型安全性の確保
3. ベストプラクティスの適用
4. 継続的な検証

**自動実行**:
```bash
npm run tdd
npm run claude:quick  # 定期的な検証
```

**使用例**:
```
/implement TASK-001: ボタンコンポーネントの基本構造
```

---

### `/review` - コードレビュー
**目的**: 品質保証と改善点の特定

**レビュー観点**:
1. **コード品質**
   - DRY原則
   - SOLID原則
   - 可読性
2. **型安全性**
   - any型の禁止
   - 適切な型定義
3. **テスト**
   - カバレッジ
   - エッジケース
4. **パフォーマンス**
   - レンダリング最適化
   - バンドルサイズ
5. **アクセシビリティ**
   - WCAG 2.2 AA準拠
   - キーボード操作
   - スクリーンリーダー対応

**出力**:
- `tmp/review-YYYYMMDD-HHMMSS.md` にレビュー結果

**使用例**:
```
/review 実装したアコーディオンコンポーネント
```

---

### `/recap` - 振り返りと知識抽出
**目的**: 学習内容の文書化と知識の蓄積

**実行内容**:
1. 実装中に得られた知見の整理
2. 再利用可能なパターンの抽出
3. 改善点の特定
4. ドキュメントの更新

**更新対象**:
- `docs/knowledge/learnings.md` - 学習内容
- `docs/knowledge/patterns.md` - パターン
- `docs/knowledge/improvements.md` - 改善提案
- `.serena/memories/` - プロジェクト知識

**使用例**:
```
/recap アコーディオン実装から得られた知見
```

---

### `/ask` - 質問
**目的**: コードベースに関する質問

**使用例**:
```
/ask このコンポーネントの状態管理はどのように実装されていますか？
```

---

### `/instruct` - 具体的な指示
**目的**: 特定のタスクの実行指示

**使用例**:
```
/instruct すべてのボタンコンポーネントにaria-labelを追加してください
```

## 🔄 典型的なワークフロー

### 新機能開発
```
1. /design 新機能の名前と要件
2. /implement タスク1
3. /implement タスク2
4. /review 
5. /recap
```

### バグ修正
```
1. /ask バグの原因調査
2. /design 修正計画
3. /implement 修正実装
4. /review
```

### リファクタリング
```
1. /design リファクタリング計画
2. /review 現在のコード
3. /implement リファクタリング
4. /review 変更後
5. /recap
```

## 🎯 効果的な使い方

### DO ✅
- 各フェーズで適切なコマンドを使用
- 小さな単位で頻繁に実行
- レビューとrecapを忘れずに
- 計画を立ててから実装

### DON'T ❌
- 計画なしでいきなり/implement
- レビューをスキップ
- 大きすぎるタスクで実行
- 知識の文書化を怠る

## 🔧 カスタマイズ

プロジェクト固有の振る舞いは`CLAUDE.md`で定義されています。  
必要に応じて、各コマンドの詳細な動作をカスタマイズできます。
