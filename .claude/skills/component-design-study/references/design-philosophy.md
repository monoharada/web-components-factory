# Design Philosophy

`component-design-study` は、Web コンポーネント開発前後の検討を「正解条件駆動」で進めるための実践ガイドです。

## Primary Users

- デザイナー
- エンジニア
- デザインエンジニア

## Goal Overlay (Current)

- 最重要 KR-1: アクセシビリティ（WCAG 2.2 AA）を達成する
- 最重要 KR-2: コンポーネント単体だけでなくテンプレート画面制作にも使える
- Non-goals: 意匠や洗練さを優先した設計
- 制約: Web 標準で現時点または近い将来に実運用可能な構成のみを採用する
- 失敗条件: 作られた成果物に A11y 違反がある
- 評価期間: 2週間で 3案件（コンポーネント + テンプレート画面）

## Study Model

- Step 分解は説明モデルであり、実務は並行実行が前提
- いつでも「現状 / 判断 / 次アクション」を Step 構造で説明できることを維持する
- Step を完了済みにしても、作例や検証で前段へ差し戻すことを前提にする

## Working Principles

- 事例調査の目的は写経ではなく、反面教師と改善余地の発見
- 観測（事実）と評価（判断）を分離して記録する
- スタディは「品質基準で絞られた合理的範囲」の中で行う
- 判断はすべてログ化し、採用/不採用の理由を残す
- 作例は「実案件へ貼り付けても破綻しない品質」で作る

## Success Criteria for This Skill

- 各案件で AA 必須項目が 100% 定義される
- 3案件すべてで Step6 以降に進める
- 各 Step の成果物と判断ログを JSON 契約で再開可能に保存できる

## Review Cadence

- 原則として Step ごとにレビューする
- レビュー観点は固定:
  - Step の目的を満たしたか
  - 次 Step に渡せる粒度か
  - Scope 逸脱がないか
  - 現在地を説明できるか
